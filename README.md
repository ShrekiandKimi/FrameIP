# Сервис доставки готовой еды

## Назначение

Приложение для оформления и отслеживания заказов доставки готовой еды из кафе и ресторанов: клиент выбирает блюда, оформляет заказ, а сервис рассчитывает стоимость, применяет скидку и назначает свободного курьера для доставки.

Консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5). В браузере можно:

- просматривать меню (список блюд);
- просматривать информацию о конкретном блюде и стоимость заказа одной порции с доставкой;
- просматривать список заказов и видеть, есть ли свободный курьер;
- просматривать информацию о конкретном заказе.

Оформление и отмена заказов, поиск, фильтрация и сортировка блюд пока доступны только в консольной версии.

## Используемые технологии

- Python 3;
- Django 5.2 — веб-фреймворк;
- HTML — разметка веб-страниц;
- CSS и Bootstrap 5.3 — оформление страниц;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Целевая аудитория

Клиенты, заказывающие готовую еду с доставкой на дом или в офис.

## Предметная область

Сфера доставки готовой еды: оформление заказов, расчёт их стоимости, взаимодействие клиентов с курьерами и отслеживание статуса доставки.

Основными объектами предметной области являются блюдо, клиент, курьер и заказ. Клиент оформляет заказ на одно или несколько блюд; сервис назначает на заказ свободного курьера. Курьер не может одновременно доставлять два активных заказа. Отменённый заказ не блокирует курьера и не учитывается в выручке.

## Основные сущности

### Dish — блюдо

Объект `Dish` представляет позицию меню, доступную для заказа.

Основные атрибуты:
- `id` — уникальный идентификатор блюда;
- `name` — название блюда;
- `price` — цена блюда.

Основные методы:
- `is_affordable()` — проверка, что цена блюда не превышает заданную сумму;
- `matches()` — проверка вхождения подстроки в название блюда;
- `validate_price()` — статическая проверка корректности цены;
- `from_data()` — создание блюда из словаря данных (JSON);
- `__str__()` — строковое представление блюда.

### Client — клиент

Объект `Client` представляет клиента, оформляющего заказы.

Основные атрибуты:
- `id` — уникальный идентификатор клиента;
- `name` — имя клиента.

Основные методы:
- `from_data()` — создание клиента из словаря данных (JSON);
- `__str__()` — строковое представление клиента.

### Courier — курьер

Объект `Courier` представляет курьера сервиса.

Основные атрибуты:
- `id` — уникальный идентификатор курьера;
- `name` — имя курьера.

Список курьеров (`COURIERS`) фиксирован и не хранится в отдельном JSON-файле.

Основные методы:
- `__str__()` — строковое представление курьера.

### Order — заказ

Объект `Order` представляет заказ клиента и связывает его с блюдами и курьером.

Основные атрибуты:
- `id` — уникальный идентификатор заказа;
- `client` — объект `Client`, оформивший заказ;
- `items` — словарь «id блюда → количество»;
- `total` — итоговая стоимость заказа с учётом скидки и доставки;
- `courier` — объект `Courier` или `None`, если все курьеры заняты;
- `status` — текстовый статус заказа («в обработке», «ожидает курьера», «отменён»).

Основные методы:
- `cancel()` — отмена заказа: снимает курьера и меняет статус;
- `__str__()` — строковое представление заказа с учётом текущего состояния.

## Взаимодействие объектов

```
Client --оформляет--> Order --ссылается на--> Dish (через items)
                        |
                        └--назначается--> Courier
```

`Order` хранит прямую ссылку на объект `Client` и объект `Courier` (а не только их идентификаторы), поэтому данные связанных объектов доступны напрямую: `order.client.name`, `order.courier.name`. Блюда в заказе хранятся как словарь `{dish_id: quantity}`, а разрешение в объекты `Dish` выполняется функцией `calculate_order_total()` при необходимости.

## Страницы веб-интерфейса

- `/` — главная страница: описание приложения и навигация (view-функция `index()`);
- `/dishes/` — меню: объекты `Dish` из `data/dishes.json` (view-функция `dishes()`);
- `/dishes/<int:dish_id>/` — страница блюда (view-функция `dish_detail()`);
- `/orders/` — список заказов: объекты `Order` из `data/orders.json` и свободный курьер (view-функция `orders()`);
- `/orders/<int:order_id>/` — страница заказа (view-функция `order_detail()`).

Если блюдо, заказ или адрес не найдены, возвращается страница с кодом статуса 404 (для несуществующих адресов — собственная страница через `handler404`, она отображается при `DEBUG = False`).

## Основные функции

### Используется в веб-интерфейсе (ПР5)
- `load_dishes`, `load_clients`, `load_orders` — загрузка данных из JSON в объекты;
- `find_dish_by_id`, `find_order_by_id` — поиск объекта по идентификатору для страниц деталей;
- `calculate_order_total`, `apply_discount`, `get_delivery_cost` — стоимость заказа одной порции с доставкой на странице блюда;
- `assign_courier` — проверка наличия свободного курьера на странице заказов.

### Отложено до следующих работ
Создание и отмена заказа, поиск, фильтрация и сортировка блюд реализованы в консольной версии и появятся в веб-интерфейсе после добавления форм и POST-запросов.

### Работа с блюдами (`models/dishes.py`)
- `add_dish`, `find_dish`, `find_dish_by_id`, `filter_dishes_by_price`, `sort_dishes`, `show_dishes`.

### Работа с клиентами (`models/clients.py`)
- `add_client`, `find_client_by_id`, `find_client_by_name`, `get_or_create_client`, `show_clients`.

### Работа с заказами (`models/orders.py`)
- `calculate_order_total` — подсчёт стоимости заказа по выбранным блюдам;
- `apply_discount` — скидка при крупном заказе;
- `get_delivery_cost` — стоимость доставки;
- `is_courier_busy`, `assign_courier` — назначение свободного курьера;
- `create_order`, `cancel_order`, `find_order_by_id` — оформление, отмена и поиск заказа;
- `get_order_status` — текстовый статус по назначенному курьеру;
- `get_unique_clients`, `get_total_revenue` — статистика по заказам.

## Назначение модулей

### `main.py`
Консольная версия приложения (сохранена с ПР3): меню, ввод данных, пользовательские сценарии.

### `frameip/`
Пакет настроек Django-проекта:
- `settings.py` — настройки проекта (в том числе `DATA_DIR` — каталог JSON-файлов);
- `urls.py` — маршрутизация верхнего уровня и обработчик `handler404`;
- `asgi.py`, `wsgi.py` — точки взаимодействия с сервером.

### `homepage/`
Django-приложение главной страницы:
- `views.py` — функция `page()` (общий HTML-каркас с Bootstrap и навигацией), view-функции `index()` и `page_not_found()`;
- `urls.py` — маршрут главной страницы.

Функция `page()` размещена здесь, потому что главная страница задаёт общий вид всех остальных страниц. Остальные приложения импортируют её.

### `dishes/`
Django-приложение меню:
- `views.py` — view-функции `dishes()` и `dish_detail()`;
- `urls.py` — маршруты приложения.

### `orders/`
Django-приложение заказов:
- `views.py` — view-функции `orders()` и `order_detail()`;
- `urls.py` — маршруты приложения.

Файлы `models.py` Django-приложений пока пусты: Django-модели появятся на следующих работах. Классы предметной области остаются в пакете `models/`.

### `models/`, `storage.py`, `utils.py`, `tests/`
Классы предметной области, JSON-хранилище, вспомогательные функции консольного ввода и автоматизированные тесты (пакет ПР3). Веб-слой использует эти классы и функции, а не заменяет их.

## Формат хранения данных

Блюда (`data/dishes.json`) хранятся списком словарей с полями `id`, `name`, `price` — при загрузке каждый элемент преобразуется в объект `Dish`.

Клиенты (`data/clients.json`) хранятся списком словарей с полями `id`, `name` — при загрузке преобразуются в объекты `Client`.

Заказы (`data/orders.json`) хранятся списком словарей с полями `id`, `client_id`, `items`, `total`, `courier_id`, `status`. При загрузке по `client_id` и `courier_id` восстанавливаются ссылки на объекты `Client` и `Courier`; при сохранении объекты преобразуются обратно в идентификаторы.

- Python 3.10+;
- Django 5.2;
- pytest;
- flake8.

```

venv\Scripts\activate
pip install -r requirements.txt
```

```
python manage.py migrate
```

## Запуск программы

Веб-версия (Django):

```
python manage.py runserver
```

После запуска открыть в браузере адрес `http://127.0.0.1:8000/`.

Консольная версия (сохранена):

```
python main.py
```
